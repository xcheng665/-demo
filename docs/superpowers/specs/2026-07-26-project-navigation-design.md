# Project 列表与独立详情页设计

## 目标

将现有“作品集”区域改为“Project / 项目”，以五个正方形项目封面作为入口。访问者点击任一封面后，进入对应的独立项目页阅读项目介绍与完整图纸序列。

本次只改动作品集页面、其详情页及必要的路由与样式；首页、能力、关于、其他、联系、AI 分身、部署与数据服务均不修改。

## 已确认的体验

### 项目列表：`/projects`

- 页面主标题为 `Project`，辅助中文为“项目”。
- 沿用站点现有导航、色彩、字体和留白语言。
- 使用 `projects` 数据中的五个项目，按编号 01–05 展示。
- 宽屏下为一排五个正方形封面；窄屏自动切换为两列。
- 每张卡显示项目编号、中文名称和英文分类；整张卡均可点击。
- 点击后进入 `/projects/01` 至 `/projects/05`。

### 项目详情：`/projects/:number`

- 详情页沿用现有站点头部，并将主导航的 Project 项保持为当前状态。
- 页面顶部提供返回 `/projects` 的入口。
- 首屏以项目首张图片为主视觉，旁侧显示中文名、英文名、类别、年份和既有中英文说明。
- 其后按 `project.images` 原有顺序纵向展示该项目的全部图纸；不新增或修改任何项目素材。
- 每张图保留可独立打开的行为，便于查看原图。

## 实现边界

### 路由

继续使用当前 `App.tsx` 中的浏览器 History API 路由机制，不引入第三方路由库、服务端渲染或新运行时。

`normalizePath()` 将识别五个项目详情路径；未识别路径仍按当前规则回到首页。现有 `public/_redirects` 的 SPA 回退可使 Cloudflare Pages 在直接访问项目详情链接时返回应用入口。

### 数据与组件

- 扩充 `Project` 的前端路由辅助信息（或从 `number` 稳定推导），不改变 `knowledge/index.json`、AI 接口或服务端函数。
- 用精简的项目卡片替换当前列表页的轮播式 `ProjectCard`。
- 新增仅负责单项目渲染的 `ProjectDetailPage`，从现有 `projects` 数据读取内容。
- 现有 PDF 预览、其他页面组件和 AI 组件不修改。

### 样式与响应式

- 新增以 `project-index-*` 与 `project-detail-*` 命名的局部样式，避免影响其他页面。
- 项目封面固定 `aspect-ratio: 1 / 1`，用 `object-fit: cover` 保持方形构图。
- 详情主视觉与信息在窄屏下转为单列；图纸保持可读宽度与稳定间距。
- 对键盘焦点保留清晰可见的交互状态，链接具有描述性标签。

## 错误处理

- 不存在的项目编号不渲染空白详情页，而是按既有未知路由规则回到首页。
- 图片加载失败时使用浏览器标准替代文本；本轮不引入新的资源加载服务或占位图系统。
- 本功能不触及网络请求、AI 服务、密钥、知识库或访客数据，因此不新增后端错误状态。

## 验收标准

1. `/projects` 仅展示五个正方形项目封面，且标题为 Project / 项目。
2. 五张封面均能点击，分别进入对应的独立 URL。
3. 每个详情页显示正确的项目资料和其完整、顺序正确的图片组。
4. 返回入口可回到 `/projects`；浏览器前进/后退正常。
5. 窄屏下列表与详情页不发生溢出或遮挡。
6. `npm run build` 成功。
7. 直接打开任一 `/projects/0N` 路径时可正确加载页面。

## 不在本次范围内

- 重构底层路由、引入 React Router、SSR/SSG 或新的框架；
- 更换部署平台、修改 Cloudflare Functions、AI 流程或知识库格式；
- 新增 CMS、数据库、内容编辑后台、登录或数据统计；
- 修改其他页面组件或重新设计全站导航。
